# 需求树 ReqTree

**项目越做越大，你和 AI 都还清楚它现在是什么样。**

给 [Claude Code](https://claude.com/claude-code) 和 [OpenAI Codex](https://developers.openai.com/codex) 用的 VS Code 插件。[English](README.en.md) | **中文**

![在对话里说一句规则，它出现在树上，再点撤销](docs/images/demo.gif)

在对话里说一句"以后每章结尾都加一道思考题"，这一轮聊完，它就出现在侧栏的树上。下周 AI 再改这一章，会自己照做。

## 你是不是也遇到过

用 AI 写代码、做课程、做游戏，头几天很顺。项目一大，下面这些事就开始冒出来。

**你自己说不清项目现在什么样了。** 一个功能改了三次，三周前定的方案被推翻过两回。哪些做完了，哪些还在做，哪条规则才是最新的，你得翻聊天记录才想得起来。

**同一件事说了好几遍，AI 还是会忘。** 在同一个对话里，AI 记得你说过的话。可它会在三个时刻忘掉：你开了一个新对话；对话太长，前面的内容被压缩成一段摘要；AI 派出一个"子 agent"（它叫来帮忙的另一个 AI）去干活，子 agent 根本看不到你们的对话。

**AI 不知道一条规则管哪个任务。** 你在做第 3 章时说"例子都要配图"，这句话是只管第 3 章，还是以后每章都这样？AI 自带的"自动记忆"会把它记下来，可不记它属于哪个任务。结果改第 5 章时，第 3 章的规则也冒出来；记的东西越来越多，前后还互相矛盾。

**规则散在好几个地方，各说各的。** 同一条规则，聊天里说过，CLAUDE.md（Claude Code 每次开工都会读的说明文件）里写过，AI 的记忆里存过，项目文档里又抄了一遍。后来你改了主意，只改了其中一处。我给自己做了几个月的课程项目查过一次：21 份规则文档、8 万多字，有 237 处重复、矛盾和过时。

**项目越大，AI 每次开工读的东西越多。** CLAUDE.md 越写越长，每开一次对话都要整份读一遍；规范文档动辄几千字，改一个标点也得从头读到尾；AI 不知道代码放在哪，只好到处搜文件。读进来的每个字都花钱，也占着对话的空间。

**AI 重复造轮子，或者写出和别处打架的代码。** 项目里明明有一个现成的函数，AI 不知道，又写了一个差不多的。

## 需求树怎么解决

用一个例子走一遍。你在做一门数据科学课，正在写第 3 章。

**第一步：你只管说话，它在后台记。** 你随口说了一句"这章的例子都要配图"。这一轮聊完，一个后台小助手（下文叫"记录员"）读到这句话，判断它是以后都要遵守的要求，不是"把这段改短"这种一次性指令。它知道你正在做第 3 章，就把这句话写进项目里一个叫 `需求树.md` 的文件，挂在"第 3 章"下面。你什么都不用做。

记录员靠一个小模型判断，偶尔会理解错：比如你只是想让这一章配图，它却记成了"所有章节都要配图"。这时打开侧栏下方的"最近改动"，每一条改动都列在那里（什么时候、改了哪个需求、改成了什么），找到记错的那条，点它旁边的"撤销"，树就回到改之前的样子。

**第二步：下次 AI 改到第 3 章，这条规则自动出现。** 下周你开了一个新对话，让 AI 改第 3 章。AI 一打开第 3 章的文件，"例子都要配图"这条就出现在它面前，不用你再说一遍。改第 5 章时，这条不会出现，因为它只属于第 3 章。规则是按文件送到 AI 手上的：执行一个任务，AI 只读到从上一级继承下来的规则，加上这个任务自己挂的规则，别的任务的规则一条都不来。

![改到哪个文件，就只带上那条路上的规则](docs/images/scope.png)

**第三步：你随时看得到全貌。** 侧栏里是一棵树：每门课、每一章是一个"需求"，挂着它的规则和状态（进行中、待做、完成）。AI 正在改哪一章，那一行会亮起来。

**第四步：规则多了，它帮你整理。** 用久了，难免有重复的、矛盾的、过时的。点一下"体检"，它会合并重复的、处理矛盾的、清理过时的。每一处改动都能撤销，只有真拿不准的才问你。

![需求树是怎么工作的：进来的信息、后台整理、存在哪、送到谁手上](docs/images/architecture.png)

## 规则、文档、记忆，各放什么

一个项目的信息有好几种，混在一起放，既费 token，又容易前后不一。需求树给每种信息安排了一个固定的位置：

| 放在哪 | 放什么 | 例子 | AI 什么时候读 |
|---|---|---|---|
| **规则**（需求树里） | 一句话就能照着做的要求 | "例子都要配图""段落不超过 4 行" | 改到对应文件时，自动出现 |
| **决定**（以"决定："开头的规则） | 你在几种做法里选定的那个，连同原因 | "决定：图表用原生 SVG，不引图表库（离线也能打开）" | 同上；AI 想推翻它，得先问你 |
| **文档**（挂在需求上） | 规则装不下的东西：为什么这样定、具体怎么做、例子、数据、进度 | 章节表、写作规范的详细解释、架构说明 | 改到对应文件时，提醒 AI 先看目录，只读需要的那几节 |
| **代码地图**（自动生成） | 这块代码里已经有什么 | "这块有 `common.js`，对外提供 `DS.toast`……" | 改到对应文件时，自动出现 |
| **AI 的自动记忆** | 和项目内容无关的事 | 你的电脑环境、你这个人的习惯 | Claude Code 自己管 |
| **CLAUDE.md** | 项目入口：这是什么项目、东西在哪 | 十几行就够 | 每次开工都读，所以越短越好 |

**规则和文档怎么分**：能写成一句"要……""不要……"、照着就能做的，是规则；需要解释、举例、配数据才说得清的，是文档。规则管"做什么"，文档管"为什么"和"具体怎么做"。同一件事只写一处：体检发现文档里写着一条树里已有的规则，会把文档里那一行删掉（先备份，可以撤销）。

**长文档只读需要的那几节。** 一份几千字的规范，AI 改一处标点用不着全读。需求树给每份挂上的长文档生成一张目录，写明每一节讲什么、在第几行到第几行，AI 先看这张几十个字的目录，再只读和这次任务有关的那几节。也可以只把文档的某一节挂到需求上，比如"写作"需求只挂写作规范里的"写作风格"那一节：在需求下写 `> 文档：规范/内容与写作.md#写作风格`。

**一个文件可以同时归几个需求管。** 比如"写作"这个需求管所有课的正文页，"数据科学课"管这门课的所有文件。改数据科学课的正文页时，两份规则都会出现；改这门课的脚本时，写作规则不出现。所以通用的写作规范只写一次，不用每门课抄一遍。两份说法冲突时，管的范围更小的那份说了算。

## 怎么装

**需要**：Node.js 18 以上、VS Code，以及 Claude Code 或 OpenAI Codex。

### 让 AI 帮你装

在你的项目里开一个 Claude Code 或 Codex 对话，把下面这段话发给它：

```text
帮我在这个项目里装上需求树（https://github.com/penstic123-code/Vibe-Friend）：
1. 运行 npx github:penstic123-code/Vibe-Friend init .（如果你是 Codex，在末尾加 --tool codex）
2. 从 https://github.com/penstic123-code/Vibe-Friend/releases/latest 下载最新的 reqtree-*.vsix，放到项目文件夹外面，告诉我放在哪
3. 不要自己运行 code --install-extension，告诉我怎么在 VS Code 里从 VSIX 安装它
```

插件要你自己点着装：在 VS Code 里用命令行装插件，会把正在跑的 AI 对话一起重启，它就没法把话说完了。装好以后，新开一个对话就能用。

### 自己装

1. 从 [Releases](https://github.com/penstic123-code/Vibe-Friend/releases) 下载 `reqtree-<版本>.vsix`，在 VS Code 扩展面板 → `…` → "从 VSIX 安装"。
2. 打开你的项目，插件会问"在这个项目启用需求树？"，点"启用"。
3. 新开一个 Claude Code 对话，照常干活。

不想用了，在侧栏齿轮菜单里点"在本项目停用需求树"。`需求树.md` 会留着，以后想用再启用。

只用命令行也行：

```bash
npx github:penstic123-code/Vibe-Friend init <你的项目目录>               # Claude Code
npx github:penstic123-code/Vibe-Friend init <你的项目目录> --tool codex # OpenAI Codex
```

Codex 的用法和差别见 [docs/codex.md](docs/codex.md)。

## 需求树长什么样

`需求树.md` 是一个普通的 Markdown 文件，你可以直接打开改，也可以全在侧栏里点。

```markdown
# P 示例课程
- 段落不超过 4 行                       ← 最顶上的规则：整个项目都要守

## W 写作
> 文件：*/ch*.html                      ← 这个需求管哪些文件：所有课的正文页
> 文档：规范/内容与写作.md#写作风格      ← 只挂这份规范里的"写作风格"一节
- 每段只带一个新东西

## C2 数据科学课 🔨
> 文件：DataScience/**                  ← 这门课的所有文件
> 文档：DataScience/_CHAPTERS.md        ← 章节表：改这门课前，提醒 AI 先看
- 不引原话，全部自己叙述
- 决定：图表用原生 SVG，不引图表库（离线也能打开）

### C2.3 第3章 🔨
> 文件：DataScience/ch03-*.html
- 例子都要配图
```

- `#` 开头的标题是一个"需求"：开头是编号，结尾是状态（✅ 完成 🔨 进行中 ⏳ 待做 ❓ 待定）
- 标题下面 `-` 开头的每一行是一条规则
- `> 文件：` 写这个需求管哪些文件，`*` 表示任意文件名，`**` 表示任意多层文件夹。没写的话，沿用上一级的
- `> 文档：` 挂参考文档，`#` 后面写节名就只挂那一节

### 需求和子需求、规则和子规则

`#` 的个数表示层级：`## C2 数据科学课` 下面的 `### C2.3 第3章` 是它的**子需求**。子需求通常管上一级的一部分文件：数据科学课管这门课的所有文件，第 3 章只管第 3 章那几页。

**上一级的规则，下一级自动也要守。** AI 改第 3 章时，读到的是三层规则：整个项目的（段落不超过 4 行）、数据科学课的（不引原话）、第 3 章的（例子都要配图）。所以一条规则只写在它管得到的最高那一层，不用每章抄一遍。

**下一级可以改写上一级的某条规则，只在自己的范围里算数。** 比如整个项目规定段落不超过 4 行，可第 1 章的开场想写长一点。给两条规则起同一个名字（方括号里的那个词），下一级那条就会替换上一级那条：

```markdown
# P 示例课程
- [段落] 段落不超过 4 行

### C2.1 第1章
- [段落] 开场段落可以到 6 行        ← 只在第 1 章里替换上面那条
```

改第 1 章时，AI 读到的是"开场段落可以到 6 行"；改别的章，还是"不超过 4 行"。你在对话里说"第 1 章开场可以长一点"，记录员会自动写成这种形式。

## 别的功能

**拿不准就问你。** 有些话只有你能定："第 5 章互动可以多一点"是这一章的例外，还是以后每章都这样？碰到这种情况，记录员先按最可能的意思记下（默认只管你正在做的这一章），再在 VS Code 右下角弹一条通知让你选。不理它也没关系，先记下的那种一直有效。

**体检。** 规则用久了会有重复、矛盾、过时。点侧栏的"体检"，它会：

- 合并重复的规则；子需求重复了上一级已有的规则，删掉子需求那条
- 处理矛盾：一条明显是后来的说法，就以它为准；判断不了的才问你
- 规则太多、又能按文件分开的需求，拆成几个子需求（比如一半规则只管正文页，就拆出一个只管正文页的）
- 整理 AI 的自动记忆：已经写进树的删掉，是项目规则的搬进树
- 整理文档和 CLAUDE.md：和树重复的那一行删掉，该进树的规则搬进树

每一处改动都记在"最近改动"里，能撤销；你撤销过的，下次体检也不会再改回去。查完写一份报告，从侧栏齿轮菜单里"上次体检报告"打开。

**代码地图。** AI 改某块代码之前，会自动拿到这块的一张"地图"：有哪些文件、每个文件开头写的说明、对外提供哪些函数和类、这块依赖哪些公共模块、发出和监听哪些信号。想知道某个函数在哪定义、谁在用，AI 会运行一条查询命令。地图不调用模型，几百个文件一秒左右就生成好，代码改了会自动更新。认得 JavaScript/TypeScript、Python、Godot 的 GDScript 和网页引用的脚本，别的语言按常见写法认。

**动手原则。** 每次开工，AI 都会读到三条原则：遇到 bug 先找根因，规则互相矛盾、架构不合理的先解决，不在表面打补丁；写新东西之前，先看项目里、标准库里、已经装的依赖里有没有现成的（借鉴了 [ponytail](https://github.com/DietrichGebert/ponytail)）；不要光照你说的做，你的要求和项目实际情况、以后好不好维护有冲突时，它要先指出问题、给出建议，你拍板后再动手。

**设置。** 都在侧栏的齿轮菜单里：记录频率（每轮记、每 3 轮攒起来一起记、暂停），开关代码地图、动手原则、记录 AI 发现的做法，排序方式，停用。

## 常见疑问

**AI 不是本来就记得我说过的话吗？**
在同一个对话里记得。问题出在它看不见的时候：新开一个对话，之前说的它全不知道；对话太长被压缩，细节只剩一段摘要；派出去的子 agent 根本看不到你们的对话，主 AI 也只拿回子 agent 的结果。需求树不指望 AI 记，而是把规则存在文件里，到时候送到它面前。

**项目有上千个文件，规则藏在某个文件夹的几行字里，AI 怎么会知道它存在？**
AI 不用去找。规则按文件编进 Claude Code 自带的"按路径加载"机制：AI 读写哪个文件，Claude Code 就把管这个文件的规则交给它，子 agent 里也一样。AI 也不用把上千个文件读一遍，每次只读当前文件那一条路上的几条规则。

**把项目结构管好不就行了？**
结构好确实会少很多问题，可文件放得整齐，不等于规则管好了。规则会越加越多，有的互相打架，有的散在 CLAUDE.md、记忆和文档里各说各的。需求树做的就是把这些一直管好，而且不用你自己动手。对还不会管项目结构的新手，它也顺便帮你把项目分清楚：每个任务管哪些文件、守哪些规则。

**AI 不会把两条矛盾的规则搞混吧？**
它能看到的矛盾，往往会挑一条照做，可不一定是你最新想要的那条；它看不到的矛盾，就更发现不了。我给自己的课程项目查过一次，21 份文档里有 237 处重复、矛盾和过时。需求树让每条规则只写一处，新说法直接改写旧规则，体检再把剩下的矛盾找出来。

## 和别的办法比

| 办法 | 能做到 | 做不到 |
|---|---|---|
| 把规则都写进 CLAUDE.md | 每次开工都读到 | 不管改哪里都整份读，越写越长越费 token；要你自己维护 |
| AI 的自动记忆 | 自动记下一些话 | 不知道一条规则属于哪个任务；越记越多、前后矛盾 |
| 自己写规则文档 | 想写多细写多细 | 要你自己记、自己改；AI 不知道哪份该在什么时候读 |
| [graphify](https://github.com/safishamsi/graphify)、[aider 的 repo map](https://aider.chat/docs/repomap.html) | 帮 AI 看懂代码结构，比需求树的代码地图更强 | 只管代码，不管你的要求和规则；都不支持 GDScript |
| **需求树** | 自动记下要求，按任务分好，改到哪才读到哪；整理重复和矛盾 | 记录员偶尔会把规则挂错位置，要靠你撤销或改 |

## 测试数据

每个实验回答一个问题。原始数据和实验条件在 [`测试数据记录.md`](测试数据记录.md)。

### 记录员会不会记错、记重复？

记录员最常碰到几种情况：你换个说法重复一条旧规则；你改了主意；你提了一条新规则；你只是让 AI 改一处；你否决了一条规则。用真实的模型把这些情况各跑 5 遍，记录员每次都做对了：重复的不加，改主意的改写原来那条，一次性的不记。

![记录员判断准确率](docs/images/chart-recorder.png)

### 和让 AI 自己维护规则文档相比呢？

模拟一段 32 轮的对话：用户陆续提 13 条长期要求，中途改主意、取消、加例外。一组让 AI 自己维护一份规则文档，一组交给需求树。AI 自己记的时候，你说"思考题取消吧"，它常常再写一条"不设思考题"，旧的那条还留着；"第 2 章只出 3 道题"这种例外，有时被它写成了全局规则。需求树直接删掉被取消的那条，例外挂在第 2 章下面。

![模拟对话后的规则毛病](docs/images/chart-confusion.png)

### 能省多少？

我的课程项目原来每开一次对话，固定要读的 CLAUDE.md 加规则约 1.4 万字。把规范拆进文档、规则挂到各自的需求上以后，固定要读的降到约 2,600 字，其余的改到对应文件时才读。做任意一门课的一章，AI 要读的规则少了三到五成。

![做某门课的一章，AI 要读多少字](docs/images/chart-chapter.png)

### 拿真实对话回放一遍呢？

把我过去几周 12 个对话里亲手打的 436 条消息按时间顺序回放：一组让 AI 像平时一样自己记进 CLAUDE.md、记忆和课程文档，一组交给需求树。需求树漏得少，被推翻的旧规则留得少，整个规则库只有另一组的三分之一大。

![回放真实对话后的规则库](docs/images/chart-replay.png)

## 目前的限制

- 规则是按文件送的。不同任务改的是不同文件时效果最好；如果所有内容都塞在同一个文件里，就没法只送一部分规则。需求挂哪些文件可以随时调，一个文件也能单独挂。
- 记录员靠一个小模型判断，偶尔会把规则挂错位置。它察觉到拿不准时会问你；没察觉的，要靠你在面板上改，或者在"最近改动"里撤销。
- 每轮对话多一次小模型调用，在后台跑，约 6 秒，不耽误你。嫌多可以改成每几轮记一次。
- Codex 没有"按文件送规则"的机制，改用索引加补送，见 [docs/codex.md](docs/codex.md)。
- 在 Windows 上开发；Mac 和 Linux 由自动测试覆盖。

## 给开发者

它是怎么搭起来的、为什么这样设计，见 [docs/architecture.md](docs/architecture.md)。

```bash
node --test test/*.test.js        # 全部自动测试（界面测试需要 Edge 或 Chrome）
node bin/reqtree.js               # 命令行用法
```

**注意**：不要在用着 Claude Code 的时候用命令行强制重装插件（`code --install-extension --force`），那会重启 VS Code 的插件宿主，Claude Code 跟着重启。
