# R5 项目首页与文档配图 🔨
- GitHub 上的文档和配图要让没接触过项目的人看懂：说明背景，不用只有作者才懂的简称（如 viberlearning）。
- README 每个痛点一节：先放图，再用几句话讲清场景、原因、做法和效果，配实测数据；不必每一步单独成段（图多字少优先）。
- （AI 发现）画图源码放在 docs/images/src/，改配图从那里改。
- README 正文不加粗。
- （AI 发现）代码地图用正则解析，不是 AST（抽象语法树），文档里不要写成 AST 解析。
- 决定：README 副标题强调信息架构的设计，夸一个具体的点，不用「优秀」「最好」这类空话；正文可以夸大一些，用于宣传
- README 图多字少：每节先放图，正文只写看懂图所需的几句话。
- 决定：对外显示名用 RuleTree（中文名「需求树」保留）；内部名字也全改成 ruletree（命令 ruletree、.ruletree/、规则文件夹 .claude/rules/ruletree/、设置项 ruletree.*），旧项目升级时自动迁移。
- 决定：README 副标题用「一套为 AI 编程设计的信息架构：每个需求一份规则文件，AI 改哪个文件，就只读管这个文件的那几份；谁改了哪条都记着，一键撤销。」（2026-10-26 代码地图删了，用户让 AI 按推荐换）
- README 的例子用「项目A」「项目B」代称，并用一句话说清它是什么项目（如一个网页应用、一门课）；不写只有作者懂的内部说法（如「搬家」「实验 A」「第十节」），图表的图例、副标题、出处同样要求。
- README 第一屏放一句定位和架构图，再用几句话说清技术上怎么做到；信息各归其位的表紧跟在痛点后面；常见问题折叠起来。
- 写 README 和其他给人看的中文说明前，先读 zh-teaching-prose 写作规范（英文用 en-teaching-prose），写完按它的审稿清单查一遍。
- 讲架构的图和段落要把通用机制与具体例子分开：通用讲法不写某个项目的业务名或文件名（如店铺、shop_door.gd），例子放进单独标注的对照区域，不混在同一个框或同一段里。
