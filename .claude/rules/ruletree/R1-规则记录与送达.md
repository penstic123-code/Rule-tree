# R1 规则记录与送达 🔨
文档：docs/architecture.md, docs/design-info-architecture.md
- 设计要优雅、不臃肿；太复杂时先反思方向、架构、底层系统是否选错，再继续加。
- 决定：去掉记录员，改由干活的 AI 按说明书（_guide.md）自己维护需求树；体检保留一次模型调用（找重复、矛盾、过时，顺带分组），直接生效、可撤销；需求树的信息结构不变
- 决定：升级旧项目时，旧版留下的 .reqtree/ 不自动清理，由用户自己删（2026-10-26 用户定；本项目的已删）。
- 决定：先判断任务属于哪个需求，再按需求加载它的规则和挂的文档，这样最有用。
- （AI 发现）Claude Code 的技能列表只占上下文约 1%，超了会先丢掉最少用的技能描述；调用过的技能正文整个会话保留，压缩后重新注入（单个最多 5000 token，总共 25000）。想做按需求的技能，先算这笔账。
- 决定：规则文件就是需求树：每个需求一个文件放在 .claude/rules/ruletree/，文件开头写管哪些文件，由 Claude Code 按路径加载，不再从一份总表编译出规则文件。
