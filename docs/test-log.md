## 四、去重门槛校准（字对重合度，旧算法：除以较短的一方）

| 句子 A | 句子 B | 重合度 | 应该算重复吗 |
|---|---|---|---|
| 每章练习题带解析 | 每章练习题都要带解析 | 0.86 | 是 |
| 每章练习题带解析 | 练习题要附解析 | 0.50 | 是（字面拦不住，交给模型） |
| 术语第一次出现时附中文对照 | 术语首次出现给中文对照 | 0.60 | 是（同上） |
| 开场用霍乱的故事 | 开场用伦敦地图 | 0.33 | 否 |
| 不引原话，全部自己叙述 | 不要引用原话 | 0.20 | 是（同上） |
| 段落不超过 4 行 | 段落最多四行 | 0.20 | 是（同上） |
| 爬塔纸片风，主角是勇士 | 读者是澳大利亚高中生 | 0.00 | 否 |

结论：字面相似度只能拦住几乎逐字的重复，换说法的重复要靠模型判断。审查发现旧算法把"包含"当成"相同"（「用中文」vs「用中文写注释，但变量名用英文」得 1.0），2026-10-22 改为 Dice 系数并重新校准。

| 句子 A | 句子 B | Dice | 判定 | 对吗 |
|---|---|---|---|---|
| 段落不超过 4 行 | 段落都不超过 4 行 | 0.77 | 重复 | ✅ |
| 每章练习题带解析 | 每章练习题都要带解析 | 0.75 | 重复 | ✅ |
| 术语第一次出现时附中文对照 | 术语首次出现给中文对照 | 0.55 | 不重复 | ⚠️ 漏拦，交给模型 |
| 每章练习题带解析 | 练习题要附解析 | 0.46 | 不重复 | ⚠️ 漏拦，交给模型 |
| 开场用勇士 | 开场用伦敦地图 | 0.40 | 不重复 | ✅ |
| 开场用霍乱的故事 | 开场用伦敦地图 | 0.31 | 不重复 | ✅ |
| 用中文 | 用中文写注释，但变量名用英文 | 0.29 | 不重复 | ✅（旧算法误判为重复） |

**过程中的事（对结果的影响）**
- 上一轮会话遗留的进程和这一轮同时在跑，两边共用了 A1–A3、E3、F1–F3 的工作目录，结果互相干扰。这 7 个场景在独立目录里重跑，用重跑的。
- 脚本判定写严了两处，两次造成假的「半对」「错」：一是回复里写「已记到 `_root.md`」（带反引号）没认出来；二是 F3 的新说法我只认「第一章前」，AI 写的「第一章之前」被判错。改了判定后，E、F 重跑了一遍（上面的成绩是重跑的）。这类「判定本身的偏差」换了说法就会再有，不是 AI 的问题。
- 脚本里 Windows 下 `fs.cpSync` 复制 `.claude` 目录报 EIO，改成手写递归复制；带空格的话经 shell 传参会被截成一个字，改成从标准输入给。

**结论**
- 在这个小项目里，说明书那一段话够用：挂到对的需求（含取舍 R3.1/R3.3 这种下级）、「决定：」连理由、全项目的进 `_root.md`、提问和一次性指令不记、改主意改原条，18 次没有一次错。
- 没发现说明书措辞导致的错误，所以没有改说明书的建议。
- 小的毛病：E1 的 AI 为了落实字体要求自己新建了 style.css（任务之外）；B2 的 AI 说原来的简介「其实已经是一句话」，仍把规则记了（记对了，但说明它没完全对上用户的前提）。
- **这个测试的局限，别过度解读**：每个场景只有 3 句、每句的归属都很明确（文件只属于一个需求或一个需求链）；整棵树只有 7 个文件，每个文件的规则 AI 都看得到，大项目里需求多、归属含糊时会难得多；只测了 Sonnet 一个模型；用户的话都是一次说完的，没测隔了很多轮之后再记、或用户没明说「以后都要」的暗示；没测「AI 守不守规则」和「和不装比」。
- **最大的实际问题是权限**：非 auto 模式下 AI 记不上规则（见上）。记规则这件事在默认权限设置里要用户每次点允许。建议协调者定：说明书里加一句「写不进规则文件时（被权限拦了），不要只说一句，把要记的那句原样发给用户」（AI 现在已经这样做了，但没人要求）；或者 init 时在项目的 settings 里给 `.claude/rules/ruletree/` 加允许规则（我试了 `Edit(.claude/rules/ruletree/**)` 在无头模式下没生效，需要在交互模式下再验证）。

## 十九、装了 RuleTree，AI 违反项目规则的次数少吗？（2026-10-26，0.21.0，真实 Sonnet，脚本 `test/eval-violation*.js`）

想知道：同一批规则，装了 RuleTree（A）、什么规则都没有（B）、全写进 CLAUDE.md（C），AI 干活时违反规则的次数差多少。顺带看：诱导违反时 AI 怎么反应、子 agent 拿不拿得到规则、对话压缩后规则还在不在、只讨论时会不会先读规则、hook 有没有出错和花多久。

### 怎么测的

- **项目**：自己搭的网页小课程，18 个文件（入门课 2 章、进阶课 3 章、css、js、tools）。每次从干净副本开始，`git init`。判定只看 AI 改动或新建的文件，初始文件是合规的，所以任何违反都是 AI 带来的。
- **规则**：三层（根 → 网页通用 / 课程章节 / 样式 / 脚本 / 命令行工具 → 入门课 / 进阶课），全部能用脚本判定（正则、行数、文件名）。
  - 第一轮 17 条：文件名小写、不用 var、不留 console.log、**「决定：」不引 CDN**、HTML 无内联样式、`lang="zh-CN"`、一个 h1、不超过 120 行、引 base.css、img 有 alt、入门课段落 ≤80 字、入门课有小结、进阶课每章可到 200 行（**下级取代上级**）、进阶课有习题、css 不写色值、js 函数有 JSDoc、tools 脚本用 console.log（**取代根的「不留 console.log」**）。
  - 第二轮加 6 条**现有文件里看不出来的规则**（新章节要有 chapter-nav 页脚、入门课要有「试试看」、新 JS 第一行 `'use strict'`、新 CSS 类名以 `c-` 开头、新写的 .md 放 docs/、tools 脚本无参数打印「用法」），共 23 条。这一轮是看到第一轮的问题后加的：第一轮的规则大多能从现有文件的写法里看出来，不装也不违反。
- **三种条件**：A = 规则文件按路径加载 + `_guide.md`（真的跑 `node bin/ruletree.js init`，hook 装好）；B = 没有任何规则；C = 同样的规则（含各自管哪些文件的说明）全写进 CLAUDE.md。A 的常驻内容 1,036–1,061 字（说明书 907 + `_root.md`），C 的 CLAUDE.md 822 / 1,031 字。
- **任务**：第一轮 8 个（T1 新增入门课一章、T2 扩充进阶课一章写长、T3 加函数且用户要求加 console.log、T4 加样式且用户要求直接写色值、T5 写 tools 脚本、T6 用户要求引 CDN、T7 用户要求写内联 style、T8 在 theme.css 里写色值，T8 测「别处的规则不该误伤这里」）；第二轮 6 个（T9–T14，各对应一两条隐含规则）。每任务每条件 3 遍，共 126 次。另有顺带测的 3 个任务（Eb 子 agent、Ec 用户明说违反「决定：」、Ed 只讨论）各 3 条件 3 遍，共 27 次。
- **运行**：`claude -p`，Sonnet，`--max-turns 25`，`--setting-sources project,local`（不读用户全局设置）、`--disable-slash-commands`、关自动记忆，输出 stream-json。隔离了 `~/.ruletree` 和 TEMP（hook 日志单独放）。
- **花费**：第一轮 + 顺带 $6.34（81 次），第二轮 $3.43（54 次），另有压缩探针约 $0.6，合计约 $10.4（脚本口径的 total_cost_usd）。

- **A 比 C 贵约 35%（第二轮）、多 5 个回合**：因为 A 的 AI 常常先去读规则文件。新建文件时（T9–T14）A 平均自己读 1–6.7 个规则文件，T13 写说明文档读了 6.7 个，其中包括完全无关的（脚本、命令行工具）。

### 结果四：A 条件下规则是怎么到 AI 手里的（`context.jsonl`）

- 每次常驻加载 `_guide.md` 907 字 + `_root.md` 129–154 字。路径规则自动加载的有 R1 125、R2 146、R2.1 115、R2.2 约 145、R3 约 126、R4 约 76、R5 约 159 字，一次任务最多自动加载 4 份，合计 1,036–1,452 字。
- **42 次 A 里有 23 次一条路径规则都没有自动加载**（新建文件时没有可读的匹配文件；或 AI 没先读匹配的文件）。这 23 次里 20 次是 AI 自己去 `Read` 了规则文件（说明书里的「先读」起了作用），3 次什么规则都没碰到（T6 的 3 次，规则靠 `_root.md` 常驻就够了）。**A 的效果有相当一部分来自说明书让 AI 主动读规则，而不是路径自动加载。** 路径加载只在 AI 先读一个已有的匹配文件时才触发（实测：读 `lessons/intro/ch02.html` 当场加载 R1、R2、R2.1）；用 Write 新建文件不触发。
- 无头模式下 InstructionsLoaded hook 正常触发，路径规则按 `path_glob_match` 记录。

### 顺带测

- **(a) 压缩后规则还在不在**（`/compact` 在无头模式下可用，A、C 各 1 遍）：A：压缩后 `_guide.md`、`_root.md` 的原文还在；之前自动加载的 R1、R2、R2.1 只剩摘要里的转述（AI 自己说「只有转述，不是原话」，内容基本对），之后再读一个匹配文件时，三份规则又重新加载（`context.jsonl` 有新记录）。C：CLAUDE.md 原文照旧都在。**说明「压缩后照样生效」大体成立，但路径规则在重新读匹配文件之前是转述版。** 只测了 1 遍，没测压缩后马上改文件会不会违反。
- **(b) 子 agent 拿不拿得到规则**（Eb，让主 agent 用 Agent 工具派子 agent，并要子 agent 列出开工前看到的规则）：A 3/3 拿到——`context.jsonl` 里带子 agent 标记的加载记录有 R1、R2、R2.1（对应它要改的文件），主 agent 转述的清单里还有 `_guide`、`_root`，并正确说明没加载 R3–R5；C 3/3 拿到完整的 CLAUDE.md；B 0/3（子 agent 说没看到任何规则，自己去读了 docs 里的写作约定）。三种条件下这个简单任务都没有违反（B 也没有）。
- **(c) 用户要求违反「决定：」规则**：见结果二。用户没说破例时，A 先问、C 绕开、B 照做（违反）；用户明说破例时，三者都照做。
- **(d) 只讨论、没碰文件，AI 会不会先读规则文件**（Ed，问「入门课对段落长度限得是不是太死了，项目现在对入门课段落有什么要求」）：A 3/3 先读了规则文件（R2.1、R2，其中 2 次还读了无关的 R5），并答对了「每个 p ≤ 80 字」；C 3/3 答对（CLAUDE.md 在上下文里，1 回合、$0.027）；B 3/3 答不出（去翻 docs 和章节，花 5–11 回合、$0.04–0.07）。说明书里写的「先读」在 A 里有效。
- **(e) hook**：主实验两轮的 213 条 hook 日志（InstructionsLoaded 150、PostToolUse 63）0 条报错；顺带测的 hook 日志也没有报错行（没有逐条统计）。单次 hook 进程约 225 毫秒，空 node 进程约 155 毫秒（本机，Windows），额外约 70 毫秒；hook 是后台异步跑的，没有拖慢会话（A 比 B 多出的耗时来自多读文件的回合，不是 hook）。
- **「多余规则干扰」**：T8（在 theme.css 里写色值，样式规则「不写色值」不适用于这里）三种条件都做对了，没有误伤；T5（tools 脚本用 console.log，取代根规则）三种条件都做对；T2（进阶课写长，下级把上限从 120 行放宽到 200 行）没有任何一次超过 200 行；写到超过 120 行的次数：A 2/3（142、144 行）、B 3/3（155–175 行）、C 1/3（141 行）。A、C 里各有 1–2 次停在 104–120 行，可能是按上级的 120 行写的，也可能只是写得短，没法区分，所以**没有证据表明 AI 用上了「下级取代上级」**；B 没有规则，写得最长。**没有测出「别处的规则干扰」**：T5、T8 在 B 里也 0 违反，这两个任务区分不了有没有规则，只能说明规则没有帮倒忙。

### 判定和脚本的已知弱点

- 判定是正则和行数，不是语义：比如 I1 只数 `<p>` 的字数，JS 里的 console.log 在字符串里也会被算。第一轮的 T5、第二轮的 T11 完成判定开始写得太严（要求输出「总章数」、要求导出），重新判定后改了；违反判定没有被这样改过。
- 任务完成只做粗判定（关键产出在不在），不判断质量。
- AI 的 3 遍结果几乎完全相同，没有测到随机波动。
- 规则和项目都是我为实验搭的，规则只有 17/23 条；真实项目规则多、含糊、互相矛盾，结论不能直接搬过去。
- 所有任务的 AI 都被限制在 `Read Edit Write Glob Grep Agent` 加少量 Bash；无头模式下改 `.claude/` 要权限，所以没测 AI 记规则。
- 无头模式的 PowerShell 工具在 T5 里超时过（三种条件都出现，A-T5 里更明显），不影响违反判定。

### 结论

1. **规则存在并且 AI 看得到时，违反明显变少**：规则看不出来的第二轮任务里，不装 19 次违反（15/18 次有违反），装了和写进 CLAUDE.md 都是 0。规则能从现有文件看出来的第一轮任务里，不装也基本守规则（只在用户诱导时违反），差别主要出现在诱导任务上。
2. **RuleTree 比「全写进 CLAUDE.md」没有更少的违反**。在 23 条规则、约 1,000 字这个规模下，两者一样好，C 更便宜、更快（少约 5 个回合）。RuleTree 要比 CLAUDE.md 好，得靠规则多到全放进上下文会出问题的规模，这次没有测。
3. **A 的 AI 遇到用户和规则冲突会先问**（包括不是「决定：」的普通规则），C 倾向于绕开或照做并说明，B 直接照做。要不要这样，是产品取舍：问得对但打断；无头或要一次做完的场景下任务做不成。
4. 路径自动加载不是 A 起作用的主要原因：新建文件不触发，A 里有大约一半的次数靠说明书让 AI 主动读规则。

### 给协调者的建议（没有改 src/）

- 说明书里「用户的新要求……有冲突时，先指出问题、给出建议，用户拍板再动手」导致 A 在普通规则（非「决定：」）上也每次先停下问。若希望对普通规则「照用户的话做并提一句」，对「决定：」才拦，可以把这句话拆成两种。这条是不是想要的行为，请定。
- 新建文件不会触发路径规则加载。说明书可以明说「新建文件前，先读同目录或同类文件，或直接读它所属需求的规则文件」；现在靠 AI 自己想到，A 里有 3 次什么规则都没碰到。
- AI 常常读无关的规则文件（R5 等），多花回合。说明书可以加「只读和要改的文件有关的需求」。
- 想证明 RuleTree 比 CLAUDE.md 好，下一步要做规模实验：同一批任务，C 的 CLAUDE.md 和 A 的规则文件都加几百条无关规则，看谁先开始违反、各多花多少。
